## 摘要

RFC-0015 把链接**目标**的有效性收紧为「仓库内且未被 git 忽略」,但检查**对象**(体系文档自身)仍只以「本机磁盘存在」为前提:docs/ 下的正式文档被忽略规则命中时 —— 粗粒度规则误配(`notes/`、`*draft*`、`tmp/` 类)或私有内容误入 —— 本机检查全绿,克隆后文档失踪,无任何环节报错。STATUS 与 tech/ 是跨会话与协作的上下文锚点,失踪使体系对协作者空转,且病灶只从「指向它的死链」间接暴露。本提案新增**检查 10**:体系文档(docs/ 全部 markdown 含 research 证据目录;根级 AGENTS.md / README.md / install.md 固定三件,存在才查)命中 git 忽略规则即报错,零豁免通道。同时把「私有内容放点前缀目录」从实现细节条款化为 structure.md 5.3(双向:私有内容有正道,体系文档禁止躲入),并配套修复检查 8 / 检查 6 不跳点前缀的既有误报 —— 条款化的前置,否则按条款行事反被检查 8 打脸。体系外(dist/ 构建产物、根目录散笔记)不问。复用 RFC-0015 的 `isIgnored` 判定,版本 v2.4.0。

## 背景与动机

**同根因的第二消费面**:检查语义(`fs.existsSync`,本机磁盘)与交付语义(git 跟踪面,克隆后可解析)的差集在 RFC-0015 已对「链接目标」封堵;但体系文档自身落入差集时 —— 文件被忽略、永不入库 —— 现状门禁无感。与死链不同,失踪没有直接报错形态:CI 只会从「指向它的链接死了」间接暴露,而报的是链接错,真正的病灶(文档没进 git)无人指出。

**失踪的两种真实形态**(下游反馈与误配推演):① 粗粒度 `.gitignore` 规则误配 —— `notes/`、`*draft*`、`docs/**/tmp/` 一类模式恰好罩住 docs/ 下某份活文档,作者本机不可见这一后果;② 私有内容误放 docs/ 非点前缀路径(个人笔记、会话草稿)—— 作者有意不提交,但文档进了体系目录却进不了 git。两者本机检查全绿,协作者克隆后 STATUS / tech / spec 直接不存在。

**通道条款化撞出的既有 bug**:「私有内容放点前缀目录」今天已能工作(collectMarkdownFiles 跳过点前缀,不入死链/占位检查),但只是实现细节 —— 检查 8 的 `walkDir` 与顶层文件分支、检查 6 的目录列举**均不跳点前缀**:建 `docs/.drafts/notes.md` 即被检查 8 报「自建活文档未登记」。通道若条款化而此洞不修,用户按条款行事反被门禁打脸,条款成废纸;此洞不修,通道保持隐式(无人知晓),下游继续发明 `docs/notes/` 地下形态,撞上门禁后再去 hack 脚本 —— RFC-0010 背景中「下游硬编码豁免、分发面分叉」的教训重演。两件事必须捆绑。

**下游真实需求推演**(是否有人「确实要忽略文档」):私有笔记/草稿 → 点前缀目录(本提案条款化);构建产物/生成的 md → 体系外目录 + .gitignore(合法,不在对象集合);敏感内容 → 不应以明文 md 入体系;证据超量 → 5.2 已有外部托管规则。结论:docs/ 内被忽略的 markdown 没有任何一种合法终态,零豁免通道成立 —— 声明式豁免清单在 RFC-0010 已驳回,理由不变。

## 目标

- 检查 10:体系文档命中忽略规则即报「体系文档被 git 忽略(克隆后不存在)」,消息给出三条处置路径(修正忽略规则 / 移出 docs/ / 移点前缀目录);默认模式即报,不挂 --strict(失踪是硬错误,不是待办)。
- 对象集合:docs/ 全部 markdown(**含 research 证据目录** —— 5.2 明文「文本类证据进 git」,证据失踪同样是损失,虽不在死链扫描集合但义务独立成立)+ 根级固定三件 AGENTS.md / README.md / install.md(**存在才查**,场景差异自动消化:场景二不复制 install.md / README.md,即不收集不报);跳过点前缀。
- structure.md 5.3 条款化点前缀通道,双向措辞;决策树补「本地私有内容」路由行。
- 检查 8 / 检查 6 跳过点前缀(对称修复,消除既有误报)。
- 复用 RFC-0015 的 `isIgnored` 与规则缓存,零依赖零配置保持。

## 非目标

- 不查体系外:dist/、coverage/ 等构建产物目录的被忽略 md 是合法状态,根目录散笔记(非固定三件)是用户自由区 —— 查了误伤面大于病灶。
- 不查全局 `core.excludesFile`(RFC-0015 同款驳回:spawn git 打破零依赖,机器偏好层,漏报方向安全)。
- 不做「体系文档不得放点前缀」的机器检查:点前缀不入扫描集合,机器无法判别内部文件是私有内容还是躲检的体系文档;对称禁令由条款承载 + PR 评审人工核对,与「登记即合法、不审内容」同一信任模型。
- 不新建固定目录:`.drafts/` 只是 5.3 的建议形态,不进 structure.md 第 2 节目录表,不产生登记义务。
- 不改变扫描对象集合(`mdFiles`):被忽略目录里的体系外 md 仍参与既有检查,口径牵动全部检查项,RFC-0015 已声明另行提案,当前无真实需求驱动。

## 提案详述

### 1.1 检查 10:体系文档忽略检测

```
function checkIgnoredDocs() {
  const files = [];
  (function walk(dir) {                       // docs/ 全部 md:不跳证据目录,跳点前缀
    for (const e of fs.readdirSync(dir, { withFileTypes: true })) {
      if (e.name.startsWith('.') || e.name === 'node_modules') continue;
      const full = path.join(dir, e.name);
      if (e.isDirectory()) walk(full);
      else if (e.name.endsWith('.md')) files.push(full);
    }
  })(DOC_DIR);
  for (const name of ['AGENTS.md', 'README.md', 'install.md']) {   // 根级固定三件,存在才查
    const full = path.join(root, name);
    if (fs.existsSync(full)) files.push(full);
  }
  const fails = files.filter(f => isIgnored(f))
    .map(f => `体系文档被 git 忽略(克隆后不存在):${relFromRoot(f)}(修正忽略规则;私有内容移点前缀目录,如 docs/.drafts/,见 structure.md 5.3)`);
  return { fails, okLine: `✓ ${files.length} 份体系文档全部未被 git 忽略` };
}
```

检查编号 10,默认模式运行(非 --template);「代码结构」注释与头注释检查项清单同步。

### 1.2 检查 8 / 检查 6 的点前缀跳过(既有误报修复)

- 检查 8:顶层 `readdirSync(DOC_DIR)` 循环与 `walkDir` 各加 `if (e.name.startsWith('.')) continue;`(对称 collectMarkdownFiles 口径);
- 检查 6:`readdirSync(RESEARCH_DIR)` 结果过滤点前缀条目(`research/.tmp/` 一类不要求登记)。

### 1.3 structure.md:决策树路由行 + 新增 5.3

决策树「产品规划」与「都不是」之间插入:

```
├─ 本地私有内容(个人笔记、会话草稿,不入库不分发) → docs/ 下点前缀目录(如 `docs/.drafts/`),见 5.3 节
```

新增小节(置于 5.2 之后):

```
### 5.3 本地私有文档(点前缀目录)

个人笔记、AI 会话草稿等不入库内容放 `docs/` 下的点前缀目录(如 `docs/.drafts/`),并自行加入 `.gitignore`。点前缀目录不入 verify-docs 任何检查与登记义务(RFC-0016);**体系文档不得放入点前缀目录** —— 躲开检查即等于从体系中失踪,PR 评审时人工核对(机器不扫描点前缀,无法代查)。
```

### 1.4 头注释与调用命令

- 检查项清单追加第 10 项;「代码结构」注释 `[1]-[9]` 改 `[1]-[10]`;
- 调用命令不变(检查 10 随默认模式运行)。

### 配套修改

- **docs/decisions.md** 第 3 节机制决策行(失踪门禁零豁免、对象集合口径、通道条款化与点前缀修复捆绑);
- **根 README**:模板版本 v2.4.0 条目(落地时);
- **meta/README.md**:RFC 注册表加行(随本 RFC 同一 commit);
- **AGENTS.md / install.md / PR 模板不动**:不涉检查细节与调用命令。

## 备选方案

| 维度 | 方案 A(本提案:docs/ + 固定三件) | 方案 B:查全部扫描对象 | 方案 C:白名单(`git ls-files` 跟踪集) | 维持现状 |
|---|---|---|---|---|
| 误伤 | 无(对象皆义务面) | 有(构建产物被忽略合法) | 有(未 add 新文档日常性误报) | — |
| 病灶覆盖 | 全覆盖(体系内失踪) | 超覆盖 | 全覆盖(且更严) | 无 |
| 依赖 | 无 | 无 | 外部命令 git | 无 |
| 语义准确度 | 「体系文档必须被跟踪」 | 「一切 md 必须被跟踪」(假命题) | 「一切文档必须已提交」(与开发中态冲突) | — |

**方案 B** 未入选:构建产物与体系外笔记的被忽略是合法状态,「一切 md 必须被跟踪」是假命题 —— 0015 同款黑名单逻辑在此不成立,因为对象不再是「被链接的东西」而是「一切文件」。
**方案 C** 未入选:RFC-0015 方案 C 同款驳回(开发中态误伤),且把「存在 + 未忽略」换成「已提交」变更了义务语义(文档工作流的 WIP 态合法存在)。
**通道备选**:仅消息提示不条款化(埋在错误消息里,改文案即漂移)与声明式豁免清单(RFC-0010 方案 B 同款驳回)均不取;条款化是唯一有规范依据、可被 AI 与人同时发现的形态。

## 影响与风险

- **模板仓库自身**:docs/ 与根级三件全部进 git,检查 10 零报错;检查 8/6 的点前缀修复在无点前缀条目的模板上零变化(--template 双模式确认)。
- **下游项目**:存量失踪文档开始报错 —— 即本次目的;三条处置路径各自可行动。粗粒度 .gitignore 误配是常见形态,属门禁收紧的正常迁移(同 RFC-0014/0015 先例)。
- **检查 8/6 修复的语义**:消除的是既有误报(点前缀本不入体系),报错集合只减不增,非放宽。
- **信任模型**:点前缀通道无法机器验证「进去的是私货不是体系文档」,依赖 5.3 禁令 + 评审人工核对 —— 残余风险为有意的恶意躲检,门禁体系对此类威胁的既有口径一贯是评审兜底(登记不审内容同理)。
- **性能**:对象集合与 mdFiles 同量级,isIgnored 有规则缓存,无感。

## 迁移与回滚计划

非破坏性变更(新增检查 + 修复误报 + 新增条款);下游迁移 = 整文件替换 + 按消息清理存量失踪。回滚 = 还原检查 10、检查 8/6 的点前缀跳过、5.3 与决策树行 —— 曾被修复消除的检查 8 点前缀误报回归,失踪文档回到静默(可逆性等于重新接受病灶)。

**验证口径**:① 模板仓库默认与 `--template` 双模式全绿;② 构造 `docs/.gitignore` 忽略 `draft-x.md` 且 `docs/draft-x.md` 存在,断言检查 10 报「体系文档被 git 忽略」;③ 根 `.gitignore` 临时加 `install.md`,断言检查 10 报根级条目(存在才查 + 固定三件生效);④ 构造 `docs/.drafts/n.md`,断言检查 8 与检查 10 均不报(通道豁免 + 修复生效);⑤ 构造 research/ 同 slug 主文档 + 证据目录,证据目录内 md 被忽略,断言检查 10 报(证据义务覆盖;检查 6 的临时未登记报错与本题无关);全部用例清理复原后复跑全绿。

## 开放问题

- [x] 根级对象为何是固定三件而非 manifest?→ 下游仓库无 manifest.txt(场景一初始化删除、场景二从不复制),脚本不可依赖;「存在才查」让场景一/二的分发差异自动消化;硬编码固定名有 `liveDocPaths`、检查 8 `FIXED_TOP` 先例(2026-09-10 起草时定)。
- [x] 证据目录是否纳入对象?→ 纳入:5.2 明文「文本类证据进 git」,证据失踪同样是体系损失;虽不入死链扫描集合,义务独立成立,对象收集独立于 `mdFiles`(2026-09-10 起草时定)。
- [x] 检查 10 是否挂 --strict?→ 不挂:失踪是硬错误(文档已不在交付面),不是初始化待办;--strict 语义是「初始化验收」,两者正交(2026-09-10 起草时定)。
- [x] 通道条款化还是仅消息提示?→ 条款化:隐式通道可发现性为零,地下形态 → 撞门禁 → hack 脚本是 RFC-0010 实测教训;消息需要规范依据;对称禁令封住躲检后门,机器查不了的部分评审兜底(2026-09-10 起草时定)。
