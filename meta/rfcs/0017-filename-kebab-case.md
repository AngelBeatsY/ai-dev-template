## 摘要

structure.md 第 4 节「文件名一律使用 kebab-case 英文,不使用下划线、空格、中文」是既存 MUST,decisions.md 第 4 节亦有「中文文件名」的不采纳决议 —— 但检查 7 只覆盖五编号目录的编号文件命名,docs/ 全域散文档(tech 增补、research 主文档、自建目录活文档、docs/ 顶层散文件)与根级文件的文件名无机器兜底:中文 / 下划线 / 空格 / 大写文件名静默入库。中文名的成本不在「美观」而在机制:markdown 链接 URL 编码(`%E4%B8%AD.md` 形态)、git 跨平台 NFD/NFC 分解(macOS 存 NFD、Windows 存 NFC,跨平台克隆后文件名乱码的经典事故)、AI 工具对非 ASCII 路径的检索稳定性;且违规随引用增长改名成本递增。本提案新增**检查 11**:对象 = 死链扫描集合 `mdFiles`(天然跳过点前缀与 research 证据目录 —— 证据文件名以原作者仓库为准,豁免与 RFC-0010 死链豁免同源)+ 根级固定三件(存在才查),仅排除检查 7 五目录内的编号文件(防双查;管辖外路径的编号形态文件如 meta/rfcs 模板 RFC 仍归本检查,否则成无人管辖盲区),豁免大写固定名 {AGENTS.md, README.md, STATUS.md},判定 `^[a-z0-9]+(-[a-z0-9]+)*\.md$`,违规即报。报告模式不取:文件名违规没有「中间态」语义(TODO 占位可稍后填,中文名不会自己变对),报告只会被忽略。版本 v2.5.0。

## 背景与动机

**既存 MUST 的兜底空白**:0014(登记)、0015/0016(有效性判据)一路补齐的都是「有明文义务、无机器核对」的缺口;文件名是最后一个同型缺口 —— 规范与不采纳决议双依据在档,约束对象(全仓库体系文档)却只有五编号目录被检查 7 覆盖。中文环境下文名(尤其 AI 生成文档时)的诱惑真实存在,静默入库后无人报错。

**严格度论证(起草时专项讨论)**:① 约束非本提案发明,本提案只是把既存 MUST 从「五目录」覆盖到「全域」,不新增规范负担;② 自由空间精确对位 —— 私有笔记与草稿走点前缀通道(`.drafts/调研草稿.md` 完全合法)、research 证据豁免、体系外不问,受限的只有体系内正式文档,而其全部价值恰在被引用 / 检索 / 跨会话交接,是中文名机制风险最大处;③ 门禁优于报告:违规无中间态语义,改名成本随引用递增,门禁把成本挡在最早时点,改名后跑检查 1 即可发现全部断链,修复可发现性好。

**病灶证据强度(如实标注)**:本候选无下游实测(0010/0015 为实测驱动,0016 为推演 + 通道洞),「中文环境诱惑」同为推演型预防;与 0016 同级 —— 预防性门禁,等首个实测病灶再立的代价是届时存量改名更痛。

## 目标

- 检查 11:对象文件名不匹配 `^[a-z0-9]+(-[a-z0-9]+)*\.md$` 即报「文件名不合 kebab-case(下划线/空格/中文/大写)」,消息指向 structure.md 第 4 节与处置路径(改名并同步修正引用)。
- 对象 = `mdFiles`(collectMarkdownFiles 现成:跳点前缀 / 证据目录 / node_modules)+ 根级 AGENTS/README/install 固定三件(存在才查,与检查 10 同构);仅排除检查 7 五目录内的编号文件 —— 编号文件含类型后缀 `.` 点,入纯 kebab 正则必误报;但排除限定于五目录路径,管辖外路径(meta/rfcs、archive 等)的编号形态文件仍归本检查,否则成无人管辖盲区。
- 豁免集 = {AGENTS.md, README.md, STATUS.md}(体系既有的全大写固定名惯例,工具生态约定俗成);小写固定名(decisions.md、install.md)天然合规无需豁免。
- 默认模式运行,不挂 --strict(合式性是恒常约束,与初始化验收正交)。

## 非目标

- 不管非 md 文件与目录名:md 是文档体系的唯一载体;目录名由 structure.md 第 1/2 节固定表约束,模板分发即定型,无漂移面。
- 不改既有条款:structure.md 第 4 节与 decisions.md 第 4 节不动,义务本已在档。
- 不管点前缀、research 证据目录、体系外路径(自由区,与 0016 口径一致)。
- 不重复管辖编号文件(检查 7 专属,见目标)。

## 提案详述

### 1.1 检查 11:文件名合式检测

```
const KEBAB_MD = /^[a-z0-9]+(-[a-z0-9]+)*\.md$/;
const FIXED_UPPER = new Set(['AGENTS.md', 'README.md', 'STATUS.md']);

function checkFileNameKebab() {
  const objects = [...mdFiles];
  for (const name of ['AGENTS.md', 'README.md', 'install.md']) {
    const full = path.join(root, name);
    if (fs.existsSync(full)) objects.push(full);
  }
  const sevenDirs = new Set(NAMING_RULES.map(r => path.join(DOC_DIR, r.dir)));  // 检查 7 管辖目录(NAMING_RULES 同源)
  const fails = [];
  let count = 0;
  for (const f of objects) {
    const base = path.basename(f);
    if (sevenDirs.has(path.dirname(f)) && /^\d{4}-/.test(base)) continue;  // 五目录内编号文件归检查 7;管辖外(meta/rfcs 等)编号形态仍归本检查
    if (FIXED_UPPER.has(base)) continue;
    count++;
    if (!KEBAB_MD.test(base)) {
      fails.push(`文件名不合 kebab-case(下划线/空格/中文/大写):${relFromRoot(f)}(structure.md 第 4 节;改名并同步修正引用,改名后检查 1 可见全部断链)`);
    }
  }
  return { fails, okLine: `✓ ${count} 个文件名全部合 kebab-case` };
}
```

检查编号 11,默认模式运行,CHECKS 与头注释检查项清单同步;`mdFiles` 沿检查 1 惯例以参数传入。

## 备选方案

| 维度 | 方案 A(本提案:门禁) | 方案 B:报告模式(不失败) | 方案 C:观望(等实测病灶) | 维持现状 |
|---|---|---|---|---|
| 约束来源 | 既存 MUST(零新增) | 同 | 同 | 同 |
| 兜底强度 | 全 | 弱(报告被忽略) | 无 | 无 |
| 误伤 | 无(豁免集覆盖合法形态) | 无 | 无 | — |
| 存量成本 | 违规即改(最早时点) | 随引用递增 | 病灶出现时存量更大 | — |

**方案 B** 未入选:违规没有中间态语义,报告模式的输出会被当作噪音忽略 —— TODO 报告模式成立的前提是「占位是合法中间态」,文件名不满足此前提。
**方案 C** 未入选:预防 vs 实测的权衡如实披露(见背景),但文件名漂移不可逆入库(引用随之生成),事后治理成本单调上升;同级先例 0016 亦以推演立项。
**维持现状** 未入选:与既存 MUST 的机器兜底路线(0014-0016)相悖,规范可信度受损。

## 影响与风险

- **模板仓库自身**:全部文件名合规(含 -template 后缀文件,均 kebab),检查 11 零报错(--template 双模式确认)。
- **下游项目**:存量违规文件开始报错,处置 = 改名 + 同步修正引用;改名是体系内操作,检查 1 提供断链全量可见性。对以中文名重度使用的存量项目,一轮清理属门禁收紧的正常迁移(同 0014-0016 先例)。
- **严格度残余风险**:「AI 生成中文名」在检查 11 下被即时拦住而非事后清理 —— 这是预期行为而非误伤;唯一残余摩擦是习惯迁移,无机制成本。
- **双查风险**:编号文件已排除(检查 7 管辖);-template 文件天然合规不豁免(留检查 11 在册,防未来新增 template 文件名漂移)。

## 迁移与回滚计划

非破坏性变更(新增检查);下游迁移 = 整文件替换 + 按消息改名清理存量。回滚 = 还原检查 11 与头注释,违规文件名回到静默(可逆性等于重新接受漂移)。

**验证口径**:① 模板仓库默认与 `--template` 双模式全绿;② 构造 `docs/Bad_Name.md`(大写+下划线)与 `docs/中文测试.md`,断言检查 11 各报一处(伴生的检查 8 未登记报错与本题无关),清理复原;③ 构造 `docs/.drafts/中文名.md`,断言检查 11 不报(点前缀通道豁免);④ 构造 `docs/specs/0001-x.spec.md`,断言检查 11 不报(五目录内编号文件归检查 7,无双查误报),清理复原后复跑全绿;⑤ 断言模板自身 meta/rfcs 的 17 份编号形态 RFC 全部计入检查 11 的 okLine 计数(管辖外编号形态归本检查,盲区封堵)。

## 开放问题

- [x] 门禁还是报告模式?→ 门禁:违规无中间态语义(TODO 报告模式的前提不成立),报告会被忽略;改名成本随引用单调递增,门禁挡最早时点(2026-09-10 起草时定)。
