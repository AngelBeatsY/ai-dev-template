## 摘要

verify-docs.mjs 检查 1 的死链判定仅为 `fs.existsSync` —— 文件系统存在性,不感知 git。两类假通过:① 链接目标被 `.gitignore`(或 `.git/info/exclude`)忽略 —— 已有下游项目出现正式文档引用被忽略的文档,作者本机检查全绿,协作者克隆/CI 上即死链,问题暴露点从开发现场后移到下游;② 链接目标(`../` 相对逃逸或绝对路径)解析到仓库根之外,链接有效性取决于检查者本机的目录布局,同一链接在不同机器判定相反。本提案把有效判据收紧为:**解析后必须落在仓库根之内,且未被 git 忽略规则命中**;忽略判定纯 Node 自解析 .gitignore(根 + 嵌套 + `.git/info/exclude`),脚本保持零依赖、无配置面,下游升级 = 整文件替换。另随本 RFC 顺带修正检查 1 既有误报:URL 编码路径(`%20` 等)未解码即判存在性(提案 1.4)。

## 背景与动机

**下游实测(泛化表述)**:某下游项目出现正式文档(交接/说明类活文档)引用被 `.gitignore` 忽略的 markdown(个人笔记、草稿落在了被排除目录)。作者本机工作区文件在,检查通过;协作者克隆后链接失效。根因是**检查语义与交付语义不一致**:文档体系随 git 分发,链接有效性应以「克隆本仓库后可解析」为准,而 `fs.existsSync` 以「检查者本机磁盘」为准 —— 两者的差集恰是被 git 排除的部分,现状门禁对此全部放行。

**仓库外链接(代码审读发现)**:检查口径只问存在性,相对链接 `../` 逃逸或绝对路径解析出仓库根时,有效性绑定检查者机器 —— 本机存在的 `../notes/x.md` 在任何 CI 的干净检出上都拦不住(目标不存在时 `existsSync` 才失败,误打误撞可报;本机恰存在则永久假通过)。

**为什么是模板侧改**:链接有效性是文档门禁的核心语义,口径偏差是模板缺陷而非个别项目失误。下游各自救济(手工 grep、口头约定)不可持续且语义无档,与前两次门禁收紧(RFC-0010 豁免、RFC-0014 登记兜底)同属模板职责。

## 目标

- 判据三分:目标存在、位于仓库根之内、未被 git 忽略;错误消息区分「死链 / 仓库外链接 / 目标被 git 忽略」,每类可判定、可行动。
- 零依赖零配置:纯 Node `fs/path` 自解析 .gitignore,不 spawn 子进程、不读 npm 依赖(延续 RFC-0012 保留的「零依赖原生 node 直接执行」契约)。
- 忽略规则源:仓库根 `.gitignore` + 链接目标沿途目录的嵌套 `.gitignore` + `.git/info/exclude`;`!` 否定、`**` 通配、目录模式、锚定语义按 git 语义的常见子集实现(已知偏差全部定向到漏报侧,见风险)。
- 不改变其余 8 项检查、扫描对象集合与调用命令。

## 非目标

- 不把「链接目标为目录」判为死链:GitHub 渲染下目录链接可点击,现状语义保留;增量最小,避免引入新误报面。
- 不查全局 `core.excludesFile`:需 spawn `git config` 取路径,打破零依赖;且全局排除是机器偏好层(编辑器交换文件等)而非项目约定,漏报方向安全。
- 不过滤扫描对象集合:被忽略目录里的 markdown 仍参与全部检查。扫描集合口径牵动所有检查项,不在本次夹带,确有噪音时另行提案。
- 不支持 gitignore 字符类 `[a-z]` 与反斜杠转义:按字面匹配,偏差漏报方向(见风险),真实项目罕见。
- 不引入声明式豁免清单:同 RFC-0010 方案 B 驳回理由(第二份会漂移的声明,当前无真实需求)。

## 提案详述

### 1.1 检查 1 判据三分

```
for (const m of scanText.matchAll(MD_LINK)) {
  const target = m[1].split('#')[0].trim();
  if (!target || EXTERNAL_LINK.test(target)) continue;
  linkCount++;
  const resolved = path.resolve(path.dirname(f), target);
  const rel = path.relative(root, resolved);
  if (rel.startsWith('..') || path.isAbsolute(rel)) {   // 逃逸(含跨盘符绝对路径)
    fails.push(`仓库外链接 ${relFromRoot(f)} -> ${target}`); continue;
  }
  if (!fs.existsSync(resolved)) { fails.push(`死链 ${relFromRoot(f)} -> ${target}`); continue; }
  if (isIgnored(resolved)) {
    fails.push(`链接目标被 git 忽略(克隆后不存在)${relFromRoot(f)} -> ${target}`);
  }
}
```

顺序即优先级:仓库外 > 不存在 > 被忽略,每链接只报最靠前的一类。

### 1.2 忽略判定(.gitignore 常见子集,`isIgnored`)

- **规则源与顺序**:根 `.gitignore` + 目标路径沿途各目录的嵌套 `.gitignore` + `.git/info/exclude`;按所在目录深度浅 → 深应用,同文件内后者胜出,与 git 一致。规则文件解析结果按目录路径缓存。
- **逐行解析**:trim 后空行与 `#` 开头跳过;`!` 前缀 = 否定;尾部 `/` = 仅目录;去尾 `/` 后含 `/` = 锚定于规则文件所在目录,否则匹配任意层级段。
- **glob 编译**:`**/` → 任意层级前缀,`*` / `?` 不跨 `/`。
- **判定对象**:目标文件自身 + 全部祖先目录逐个匹配(目录规则如 `build/` 经祖先命中即排除其下文件)。
- **已知偏差(全部漏报方向,即退回现状,不产生新失败)**:git 为性能不下降已排除目录,故 `build/` + `!build/keep.md` 在 git 中 keep.md 仍被排除,本实现按路径独立判定为未忽略;字符类与转义按字面匹配。

### 1.3 头部注释检查项 1 改写

```
 *   1. 死链:相对链接目标必须存在、位于仓库根之内且未被 git 忽略(仓库外链接与被忽略目标
 *      单独报错;围栏代码块与行内代码内的引用原文不检查;research/ 同 slug 证据目录内的
 *      第三方引用原文不检查,见 structure.md 5.2)
```

### 1.4 顺带修正:URL 编码路径解码(检查 1 既有缺陷)

链接目标中的 URL 编码(`%20` 空格等)未解码即做存在性判断,编码路径(渲染器与 GitHub 均支持)被误报死链 —— 与本次判据收紧同在检查 1 同一判定链,拆开须两次迁移,随本 RFC 一并修正:剥锚后 `decodeURIComponent`(畸形 `%` 序列按原文判定),再走逃逸 / 存在 / 忽略三分。

- **docs/decisions.md** 第 3 节机制决策行(判据三分、偏差定向漏报侧、备选 B/C 驳回理由);

## 备选方案

| 维度 | 方案 A(本提案:自解析 .gitignore) | 方案 B:spawn `git check-ignore` | 方案 C:白名单(目标必须在 `git ls-files` 跟踪集) | 维持现状 |
|---|---|---|---|---|
| 依赖 | 无(零依赖契约保留) | 外部命令 git(CI 无 git 即坏) | 外部命令 git | 无 |
| 与 git 行为一致度 | 常见子集,极端模式有已声明偏差(漏报侧) | 100% | 100% | — |
| 开发期误伤 | 无(未 add 新文件不受影响) | 无 | 有(新建文档互链在 add 前全报) | — |
| 脚本升级 | 整文件替换 | 整文件替换 | 整文件替换 | — |
| 病灶覆盖 | 全覆盖(忽略 + 逃逸) | 全覆盖 | 全覆盖(且更严) | 无 |

**方案 B** 未入选:与 git 行为完全一致是真实收益,但代价是打破 RFC-0012 显式保留的零依赖原生执行契约 —— 分发面脚本嵌入任意宿主,不预设宿主 CI 有 git;偏差已定向到漏报侧(退回现状),换依赖不值。
**方案 C** 未入选:「必须被跟踪」口径最严,但把开发中态(新建未 add)误判为死链,文档驱动工作流(new doc 引用 new doc)会日常性误伤;有效性问题出在被**排除**的文件上,不在未**暂存**的文件上,黑名单口径(A)恰中病灶。
**维持现状** 未入选:下游实测存在正式文档引用被忽略文档的假通过,仓库外链接跨机器判定不一致 —— 门禁核心语义失真。

## 影响与风险

- **模板仓库自身**:无被忽略 markdown、无仓库外链接(验证口径 ① 双模式确认),行为零变化。
- **下游项目**:存量违规链接开始报错 —— 即本次目的;三类消息各自给出处置路径(改指入库路径 / 将目标入库 / 删除链接)。升级后需清理一轮,属门禁收紧的正常迁移,同 RFC-0014(存量补登记)先例。
- **误报风险**:gitignore 解析偏差已定向到漏报侧;不预测「将来可能 add」—— 被 .gitignore 排除的文件按定义永不入库,判死语义正确。
- **性能**:忽略规则按目录缓存,文档规模(10³ 文件 / 10⁴ 链接量级)毫秒级,无感。

## 迁移与回滚计划

判据收紧不改任何接口与命令;下游迁移 = 整文件替换 + 按消息清理存量。回滚 = 还原检查 1 与头注释、还原 structure.md 行,曾报错的链接回到假通过(即本次收紧的可逆性等于重新接受病灶)。

**验证口径**:① 模板仓库默认与 `--template` 双模式全绿;② 构造用例:`.gitignore` 临时加 `tmp-verify-0015/`,临时 md 引用 `tmp-verify-0015/x.md` 与 `../outside-x.md`,断言分别报「被 git 忽略」「仓库外链接」,引用入库文件的链接断言通过,清理复原;③ 嵌套用例:子目录 `.gitignore` 规则命中目标,断言仍报;④ 否定用例:`!` 规则恢复的目标断言不报;⑤ 含 `%20` 编码的临时链接断言通过(1.4)。
