# RFC-0010:research 证据目录的检查豁免(verify-docs 结构语义豁免)

## 摘要

verify-docs.js 死链检测遍历全部 markdown,把 research 证据目录(structure.md 5.2)内的第三方引用原文也当作本文档体系检查 —— 证据文件里的相对链接指向第三方仓库(`LICENSE`、`CONTRIBUTING.md` 等),必然误报。按 5.2 组织证据的下游项目已实测触发 9 个死链误报,并以直接修改 verify-docs.js(在 walk() 中硬编码本项目证据目录路径)的方式自行豁免。本提案把豁免做成模板机制:判据从 5.2 既有约定推导 —— `docs/research/` 下目录 X 与主文档 X.md 并存即证据目录,其内 markdown 不入检查;主文档与登记义务照常。脚本保持模板原版,下游按 5.2 组织证据即自动豁免。

## 背景与动机

**误报证据(实测,2026-09-02)**:用模板原版脚本跑按 5.2 组织了多文件调研的下游项目,9 个死链全部落在证据目录内的第三方 README 摘录,链接目标均为**原作者仓库**的相对路径(`LICENSE`、`CONTRIBUTING.md`、`benchmark/RESULTS.md`、`./docs/how-to-add-a-new-backend.md` 等)。这些摘录属 5.2 语境下的「源码原文/原始数据」类证据,其相对链接以原作者仓库为根,在本仓库必然不存在 —— 不是文档缺陷,是检查对象认错了边界。

**下游已发生的自力救济及其代价**:实测中,下游项目在 walk() 中加入硬编码豁免(把本项目证据目录的 slug 与子目录名写死进正则)。三个问题:

1. **分发面分叉**:verify-docs.js 在 manifest.txt 白名单内(「模板自带」)。下游修改后,模板侧后续演进无法整文件同步,要么手工合并要么丢弃豁免;
2. **项目专属路径进入通用工具**:slug 与子目录名写死,每个下游都得重写;且只豁免写死的已知子目录,证据目录将来新增 markdown 即漏;
3. **豁免语义无档**:「这些文件是第三方引用原文」只存在于代码里,规范与注册表无痕迹。

**为什么是模板侧改**:证据目录是模板自定义的概念(5.2),按它组织的下游必然累积第三方 markdown 证据 —— 该豁免是普遍需求,不是个别项目特例。机制放模板里,下游删除硬编码、整文件换回即可。

## 目标

- 豁免判据复用既有规范(5.2 同 slug 证据目录),不引入新配置、新标记、新命名约定。
- verify-docs.js 保持零依赖、无配置面;下游升级 = 整文件替换。
- 主文档出站链接(含指向证据文件的相对链接)仍全检;登记义务(检查项 6)不变 —— 豁免不等于失踪。

## 非目标

- 不豁免主文档(research/<slug>.md)的任何检查。
- 不处理 design/assets/(5.1 文本资产为 html/css/svg,markdown 设计说明固定在顶层,无此需求)。
- 不引入声明式忽略清单(备选方案 B,当前需求撑不起配置面成本,留作自建目录确有豁免需求时的未来扩展)。
- 不改变检查项 6 对证据目录的登记要求。

## 提案详述

### 1.1 verify-docs.js:walk() 前收集证据目录并在下降时跳过

```
// ---------- 收集 markdown 文件 ----------
// structure.md 5.2:research/ 下目录 X 与主文档 X.md 并存时,X 为证据目录(第三方引用原文,只读落档)。
// 证据内 markdown 的相对链接以原作者仓库为根,不属本文档体系,不入死链/占位检查(RFC-0010)。
// 主文档 X.md 与登记义务照常 —— 豁免不等于失踪。
const researchRoot = path.join(root, 'docs', 'research');
const evidenceDirs = new Set();
if (fs.existsSync(researchRoot)) {
  for (const e of fs.readdirSync(researchRoot, { withFileTypes: true })) {
    if (e.isDirectory() && fs.existsSync(path.join(researchRoot, `${e.name}.md`))) evidenceDirs.add(e.name);
  }
}
const mdFiles = [];
(function walk(dir) {
  for (const e of fs.readdirSync(dir, { withFileTypes: true })) {
    if (e.name === '.git' || e.name === 'node_modules' || e.name === '.tmp' || e.name.startsWith('.')) continue;
    const p = path.join(dir, e.name);
    if (e.isDirectory()) {
      if (path.dirname(p) === researchRoot && evidenceDirs.has(e.name)) continue;
      walk(p);
    }
    else if (e.name.endsWith('.md')) mdFiles.push(p);
  }
})(root);
```

要点:在目录下降处跳过(非逐文件判断),证据目录内任意深度的嵌套子目录(raw/、readmes/、src/ 及其内部)一并豁免;豁免同时生效于死链(检查 1)与 TODO 报告(检查 2)—— 第三方内容出现占位标记同样是无意义噪音。其余检查不受影响:检查 6(登记)读目录清单而非扫描集合,证据目录仍 MUST 登记且清单引用的路径仍校验存在 —— 豁免不等于失踪;检查 7 只覆盖五个编号目录,与 research/ 无关。

### 1.2 structure.md 5.2 bullet 列表追加一条(置于「登记」之前)

```
- **检查豁免**:证据目录内 markdown 为第三方引用原文(相对链接以原作者仓库为根),verify-docs 不作死链与占位检查;主文档与证据登记义务照常 —— 豁免不等于失踪(RFC-0010)。
```

### 1.3 verify-docs.js 头部注释检查项 1 补半句

```
 *   1. 死链:全部 markdown 相对链接指向的文件必须存在(围栏代码块与行内代码内的引用原文不检查;
 *      research/ 同 slug 证据目录内的第三方引用原文不检查,见 structure.md 5.2)
```

### 配套修改

- **meta/README.md**:RFC 注册表加行(随本 RFC 同一 commit);
- **落地时同步**:docs/decisions.md 第 3 节机制决策行(判据从 5.2 推导、豁免 ≠ 失踪、备选 B/C 驳回理由);根 README 模板版本 v1.10.0 条目;
- **AGENTS.md 不动**:未引用 verify-docs 检查细节,检查范围收窄不属协作规范层。

## 备选方案

| 维度 | 方案 A(本提案:同 slug 结构判据) | 方案 B:声明式忽略清单(verify-ignore.json) | 方案 C:文件内标记 | 维持现状(下游各自改脚本) |
|---|---|---|---|---|
| 下游成本 | 零(按 5.2 组织即自动豁免) | 维护配置文件 | 逐文件加标记,且违反 5.2 只读 | 每项目重写硬编码 |
| 配置面 | 无 | 新增(格式/校验/失效条目) | 无 | 无 |
| 脚本升级 | 整文件替换 | 整文件替换 + 配置兼容 | 整文件替换 | 手工合并 |
| 语义有档 | 是(5.2 条款) | 是(配置文件) | 散在内容里 | 否(只存在于各下游代码) |

**方案 B** 未入选:「这是证据」已由目录结构与 5.2 条款编码,配置文件是第二份会漂移的声明;其增量能力(豁免任意路径)当前无真实需求 —— design/ 资产无 markdown,自建目录(plan/ 等)内容是第一方活文档本就该查。留作未来扩展,届时与本机制并存不冲突。

**方案 C** 未入选:5.2 只读规则 —— 证据落档不回改,给第三方内容添加标记本身就是改写证据。目录级标记文件(.verify-ignore)虽不改内容,但属于新建约定,可发现性与判据自明性均劣于 A(复用既有结构)。

**维持现状** 未入选:实测已有下游自行硬编码 —— 分发面分叉 + 项目路径进通用工具 + 语义无档,三者都是治理退化。

## 影响与风险

- **模板仓库自身**:docs/research/ 仅模板与示例行,无证据目录,evidenceDirs 恒空,行为零变化(--template 模式验证)。
- **下游项目**:删除本地对 verify-docs.js 的硬编码豁免、整文件替换为模板版;9 个误报消失,无新增失败。证据目录内 markdown 同时退出 TODO(template) 报告(第三方内容本不该含占位标记,噪音消除)。
- **误豁免风险**:第一方 markdown 被放进证据目录后将失去检查。既有规则已封堵:5.2 规定主文档 MUST 平铺、证据目录只放引用原文;检查项 6 对未登记目录报错;证据清单条款要求主文档登记全部证据。三层兜底下,残余风险可接受。
- **判据边界**:无同 slug 主文档的 research/ 子目录(不合 5.2 形态)不豁免,其内 markdown 照常检查 —— 判据偏向从紧。

## 迁移与回滚计划

非破坏性变更:纯新增判据,不修改既有检查语义。回滚 = 还原 walk() 与注释、删除 5.2 新增 bullet;曾被豁免的文件回到检查范围,若存在真死链会在回滚后的运行中暴露(即豁免的可逆性等于重新接受误报)。下游迁移:删除本地对 verify-docs.js 的修改,替换为模板新版;已在 5.2 形态下的证据目录自动获得豁免,无数据迁移。

**验证口径**:① 模板仓库默认与 `--template` 双模式全绿(无证据目录,行为不变);② 临时构造「同 slug 主文档 + 证据目录(内含指向不存在文件的 md)」,断言检查 1 不报该死链,清理后复原;③ 构造无同名主文档的 research 子目录内含死链 md,断言检查 1 仍报(判据从紧生效;检查 6 若因临时项未登记报错,与本题无关,清理复原)。

## 开放问题

- [x] 豁免粒度:目录级(下降时跳过)还是文件级(逐文件判断)?→ 目录级:递归覆盖任意嵌套证据子目录,实现与语义一致(整个子树都是引用原文);文件级需逐个判断路径前缀,无增量收益(2026-09-02 起草时定)。
- [x] 是否要求证据目录额外满足「非空」或「含取证脚本」等条件?→ 不要求:同 slug 并存已是 5.2 的强制形态,额外条件制造第二份判据,漂移无收益(2026-09-02 起草时定)。
