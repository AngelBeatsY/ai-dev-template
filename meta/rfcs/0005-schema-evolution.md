## 摘要

现行规范把「改 schema」仅用作分级信号 —— workflow.md 第 2.1 节将其列为小改排除条件、第 2.3 节将「数据格式迁移」列为重大触发 —— 分级只回答「走什么流程」,不回答「迁移怎么写才安全」;dev-standards.md 十节对 schema 演进零约束,迁移纪律完全依赖各会话自行发挥。本提案吸收一份外部项目数据库迁移规范(conventions 级文档,生产环境长期沉淀,含 15 条常见陷阱、多条附事故日期)中项目无关的实战原则,在 dev-standards.md 新增「Schema 与数据演进」一节,十条纪律:演进只走迁移、只增不改、版本名不复用、命名保序、幂等与兜底、兼容存量数据、失败不静默、多目标一致、测试同源、快照与增量分离;迁移工具、目录、执行时机与方言差异等机制细节由 tech-stack.md「项目惯用法」声明承接,维持「模板管下限、项目声明实现」的既有分层。无持久化 schema 的项目删除该节(git-workflow.md 第 6 节「可选节」先例)。来源项目特定内容不采纳:三后端方言表、自研迁移器行为、squash 操作步骤。

## 背景与动机

**证据一(dev-standards 零条款)**:dev-standards.md 全文检索 schema / 迁移 / migration / 数据库,仅 2 处命中且均非演进语境(第 28 行日志级别语义「状态迁移」、第 64 行最小权限「数据库账号」)。十节开发规范覆盖错误处理、日志、测试、安全、依赖,唯独对最易产生静默数据事故的 schema 演进没有任何条款。

**证据二(分级信号不构成纪律)**:workflow.md 第 2.1 节(「不改数据库 schema,不影响持久化数据格式」)与第 2.3 节(「数据格式迁移」触发 RFC)只决定流程级别;spec-template.md「数据结构」节指导语只要求列出类型与约束,均不约束迁移文件本身怎么写、怎么命名、怎么演进。本模板明确支持「并入现有项目」场景(install.md 场景二),已带迁移资产的项目按本模板协做时无纪律可循。

**证据三(触发源)**:维护者调研一份外部项目的数据库迁移规范,其中版本名复用导致静默丢变更、文件名字典序与交付序反序、测试 DDL 与生产 schema 漂移(测试全绿、生产缺列)等教训均系项目无关的通用事故形态,提炼为条款构成提案主体;绑定其技术栈的部分(三后端方言表、自研迁移器、特定部署平台)不采纳。

## 目标

- 把 schema 演进的最小纪律集写为语言无关、迁移器无关的 MUST / SHOULD 条款:防静默丢变更、防多环境漂移、防测试与生产 schema 脱节。
- 落点选在施工必读路径上:dev-standards.md 是 AGENTS.md 第 2 节「施工 / 改代码」路由的必读文件,不新增独立规范文件。
- 机制细节由 tech-stack.md「项目惯用法」声明承接,不改变「dev-standards 定必须达到什么、tech-stack 定具体怎么做」的分工。

## 非目标

- 不预设迁移工具与框架(不绑定 alembic / flyway / 自研脚本);命名格式 `YYYY-MM-DD-NN_<语义>` 为 SHOULD 级建议,条款强制的是「字典序 = 交付序」这一结果。
- 不规定 schema 管理范式(schema-first / migration-first / ORM 自动迁移由项目在 tech-stack.md 声明)。
- 不涉及数据备份、灾备与生产运维 SOP(按 structure.md 第 5 节决策树归 `docs/deploy/`)。
- 无持久化 schema 的项目不承担义务:删除新节与对应声明项即可。

## 提案详述

### 1.1 dev-standards.md 新增第 8 节「Schema 与数据演进」(原第 8 / 9 / 10 节顺延为第 9 / 10 / 11 节)

插入位置:第 7 节「依赖管理」之后 —— 两者同属「引入变更的管理」;重排符合 writing-style.md 第 2 节「插入新节时重排后续编号」的既有规则。条文:

```markdown
## 8. Schema 与数据演进

涉及持久化 schema(数据库表结构、索引等)的项目适用;无持久化 schema 的项目删除本节,并在 tech-stack.md「项目惯用法」中省略对应声明。迁移工具、目录与执行时机由 tech-stack.md「项目惯用法」声明。

- **演进只走迁移**:schema 变更 MUST 以版本化迁移文件承载;应急手工改库后 MUST 补迁移对齐,不留「库与迁移资产不一致」状态。迁移按稳定顺序执行一次并记录版本,已应用版本跳过。
- **只增不改**:已提交的迁移文件 MUST NOT 修改或重命名 —— 下游环境可能已应用旧文件,改动即漂移;修正 schema 一律新增迁移。
- **版本名不复用**:迁移版本标识(文件名)MUST NOT 复用,已删除的同样不复用 —— 版本记录按名跳过,同名新内容永不执行,静默丢变更。
- **命名保序**:执行序由文件名字典序决定时,命名 MUST 保证字典序 = 交付序。统一 `YYYY-MM-DD-NN_<语义>` 格式(SHOULD):NN 两位零填充(一位序号在同日第 10 个文件出现时,`-10` 会按字典序排到 `-1`、`-2` 之前),禁止带序号与无序号文件混排,日期写建档实际日期、禁止预写未来日期占位。
- **幂等与兜底**:迁移 SHOULD 幂等(重复执行无害,如 `IF NOT EXISTS`);无法幂等的操作(改名、删列、重建)MUST 依赖版本记录保证只执行一次,并在文件头注明。
- **兼容存量数据**:新增 `NOT NULL` 列 MUST 带 `DEFAULT` 或在同迁移内回填;删列删表前 MUST 确认无存活引用。
- **失败不静默**:迁移失败 MUST NOT 被跳过或忽略后继续对外服务 —— schema 不完整不对外;执行机制 SHOULD 做到单版本失败整体回滚、修复后可安全重试(实际行为在 tech-stack.md 声明)。
- **多目标一致**:同一变更覆盖多个部署目标(多数据库方言、多环境)时 MUST 逐目标落地,缺一即漂移;跨方言差异(幂等语法支持、默认值可用函数、partial index 支持)MUST 在 tech-stack.md 登记。
- **测试同源**:涉及 schema 的测试,其建表来源 MUST 与生产同源(同一基线 + 迁移,或与之对齐的 DDL),防止「测试全绿、生产缺列」。
- **快照与增量分离**:存在初始化快照(基线 SQL / seed)时,快照冻结为历史时点,MUST NOT 随每次变更改写 —— 全新环境走「快照 + 全量迁移」收敛到当前结构;快照唯一合法的更新通道是受控 squash(确认全部环境已应用相关迁移 → 并入快照 → 删除已并入的迁移文件)。
```

## 影响与风险

- **编号顺延**:dev-standards.md 第 8 / 9 / 10 节 → 第 9 / 10 / 11 节;节号引用同步仅 2 处(§1.3 已穷举),符合 writing-style.md 第 2 节既有规则,非豁免。
- **无库项目成本**:新节首段显式声明删除路径,与 git-workflow.md 第 6 节「不采用的团队删除本节」同先例;tech-stack.md 对应声明项标注适用范围。
- **条款强度取舍**:来源项目的部分铁律在本提案降级为 SHOULD(幂等、单版本回滚、命名格式)—— 有意取舍:模板锁「防静默丢变更」级别的下限,机制能力差异归项目声明;锁得过死会错误约束无版本表机制的简单项目。
- **抽象化损失**:三后端方言表等具体陷阱不入条款,以「跨方言差异 MUST 登记」承接 —— 逐方言知识应由实际持有多方言的项目自行登记,模板预写反而制造噪音。
- **兼容性**:纯文档变更,无代码、无数据迁移;已初始化项目升级时按 README 版本条目对齐。

## 迁移与回滚计划

不适用(非破坏性变更):全部为新增条款与声明项,不改变既有条款语义;回滚 = revert 对应 commit 并还原节编号与两处引用。

## 开放问题

- [x] 「失败不静默」条款强度:来源项目实践是 fail-fast 阻断启动 + 重启自愈;但存在「迁移失败、旧 schema 可降级服务」的合理场景(如非关键表新增失败)。MUST NOT 静默是否过强、阻断行为是否应整体下放 tech-stack.md 声明?→ 维持现文:MUST NOT「静默忽略后继续对外服务」是模板应锁的下限(与版本名复用同属静默事故形态);「阻断启动 vs 降级服务」属机制选择,由 tech-stack.md 声明承接(2026-09-02 决议)。
- [x] 「测试同源」管辖范围:条文现写「涉及 schema 的测试」;纯 mock 单测不建表自然豁免,但集成测试用容器库跑真实迁移的项目是否须额外验证迁移可重放?→ 维持现文:建表来源同源即达标,迁移可重放验证属机制能力,由项目在 tech-stack.md 声明承接,不入条款(2026-09-02 决议)。
- [x] 命名保序:强制「字典序 = 交付序」结果(MUST)已定,但 `YYYY-MM-DD-NN` 具体格式 SHOULD 是否会被高频迁移项目绕开(如改用秒级时间戳)?若接受绕开,§1.4 摘要行是否需同步?→ 关闭:等价方案(秒级时间戳等)天然满足 MUST 结果约束,格式建议不构成排除;AGENTS.md 摘要行未提格式,无需同步(2026-09-02 决议)。
