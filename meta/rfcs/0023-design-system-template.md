## 摘要

structure.md 第 5.1 节已把「页面规范、设计系统类持久参考」定义为 `docs/design/` 下自建活文档,但末条留口「完整生命周期规则待真实使用后按需增补」——实例化方式、章节骨架、版本纪律至今空白;这是体系内唯一被点名却没有模板的文档类型(R2 的模板复制原则对它无承载:它不是流水产物)。某下游项目的自绘 UI 实践兑现了「真实使用」前提:其设计系统活文档经三版演进(前两版废弃归档后合并统一)稳定在千行量级,演进中事故驱动补建出一组可泛化的治理机制——token 三列表格式、语义色矩阵、页面类型表、Z 轴层级模型、待回填台账(规范与代码差异只登记不重构)、冲突裁决表、外部优化清单并入时的索引化瘦身纪律。本提案把这些机制提炼为零默认值的章节骨架,新增 `docs/design/design-system-template.md`(活文档表单模板,≤200 行),并兑现 5.1 留口:实例化为 `docs/design/design-system.md`(文件名固定、无状态机),视觉值变更 MUST 记「变更记录」递增版本号。机制节按样本暴露度分层声明(约三至四成为样本特有机制),实例化以裁剪走查为第一步(不适用整节即删、v0.1 记裁剪结果),失效信号与退出条件内置——两份实践形态分叉即撤模板回退纯生命周期规则。与 RFC-0006 非目标同侧互补:0006 划定「token 表、组件规范不进模板」并解决了设计稿引用设计系统时的标注纪律,本提案解决被引用的设计系统自身怎么建——只给骨架与治理机制,零视觉值。

## 背景与动机

**证据一(体系留口未兑现)**:structure.md 第 5 节决策树与第 5.1 节把「页面规范、设计系统类持久参考」归入 `docs/design/` 活文档,登记义务已闭环(RFC-0014:README「自建活文档清单」+ verify-docs 检查 8 双向校验),但实例化面为零——无模板、无章节骨架、无版本纪律,5.1 末条明文「完整生命周期规则待真实使用后按需增补」。对照之下,流水产物五类(brief/spec/tasks/design/RFC/ADR)全有模板;design-template.md「设计基准」节要求填「设计系统 / 组件库:<链接或『自定』>」,自绘项目填「自定」之后无任何结构承接——引用链的前端(设计稿标注纪律,RFC-0006 已补)有了,被引用的后端(设计系统本体)仍是从空白摸索。

**证据二(下游实践可泛化机制盘点)**:某下游项目自绘 UI(无组件库),自建设计系统活文档从空白起步,演进路径为两版废弃归档、第三版合并统一为单一权威源,稳定在千行量级、20+ 章节。演进中事故驱动补建的机制,逐项具项目无关性:

- **token 三列表格式**(Token | 值 | 用途)与「新样式先进 token 再写组件类」纪律——源头治理硬编码色值;
- **语义色矩阵**(语义 × 填充 / 文字 / 弱底 / 边界)+ 使用红线(每条语义色「只表达什么、不用于什么」)——语义一致性可判定化;
- **页面类型表**(类型 | 代表路由 | 核心任务 | 排版目标)+「先定类型 → 套骨架 → 再填组件」——新页面排版不另起炉灶;
- **Z 轴层级模型**(层 | z-index | 底色 | 边与影 | 内容白名单)+ 禁散装大值——布局层级可判定;
- **待回填台账**(规范与代码差异只登记、不主动重构、完成划掉)——规范可先行于代码而不失控,这是下游实践最重要的治理发明;
- **冲突裁决表**(冲突点 | 旧值 | 落定 | 处置)——多版并存期的裁决留痕,正文不留双值注释;
- **配套自包含 HTML 规范页**(演示组件即规范实现)——视觉规范的可视化交付形态,且实践过「规范页先行、代码照实现、正文收编」的工作流;
- **外部优化清单并入的索引化瘦身纪律**——历史清单只留索引、详情归正文或台账,防附录膨胀(该实践曾从 30 条详述瘦身重整)。

**证据三(摸索成本)**:上述机制均为演进中事故驱动补建——硬编码色值事后收编、三版合并冲突裁决、外部清单膨胀后二次瘦身。若骨架自带这些机制位,下游首版即获得;第三版才补齐的教训不该由每个自绘项目重付。

## 目标

- 新增 `docs/design/design-system-template.md`:零默认视觉值的章节骨架,内嵌治理机制位(token 表、语义色矩阵、层级模型、待回填台账、冲突裁决、变更记录),≤200 行。
- 兑现 structure.md 第 5.1 节留口:实例化方式(文件名固定 `design-system.md`)、版本纪律(变更记行 + 递增版本号)、无状态机定位(活文档)。
- 与 design-template.md「设计基准」行衔接:「自定」补实例化指引,引用链闭环。
- 适用判据显式化:自绘 UI 用模板;组件库项目不建,只填链接——模板头部门槛挡住不适配场景;实例化第一步为裁剪走查(不适用整节即删、v0.1 记裁剪结果),模板传递骨架与机制位而非「设计系统必须长全部章节」的心智模型。

## 非目标

- 不带入任何具体视觉值:模板全部值为 `TODO(template)` 占位,零色值、零字号、零断点默认——与 RFC-0006 非目标(token 表、组件规范不进模板)同侧。
- 不提供配套 HTML 规范页模板:可视化规范页为可选资产,由项目自建,字段表留行承载链接;千行级 HTML 模板自身即维护负担,强制即流程税。
- 不改 verify-docs.mjs:新模板以 `-template.md` 后缀落入既有豁免面(检查 2 占位分布、检查 8 活文档收集、检查 11 命名检查的对象排除均按后缀判);manifest.txt 为目录级白名单,`docs/` 全域已覆盖。
- 不动 AGENTS.md:活文档不经 AGENTS 路由,承载面在 structure.md;行数红线不增。
- 不加状态机:设计系统是活文档,无状态机(RFC-0006「检索入口与状态机归 spec」的活文档对偶:生命周期 = 持续更新 + 版本纪律)。
- 存量项目不追溯:未自建设计系统的已初始化项目零增量;已自建的项目 MAY 参照模板重排骨架,非义务。

| 维度 | 方案 A(本提案:骨架模板 + 5.1 增补) | 方案 B:只增补 5.1 规则,不建模板 | 方案 C:骨架并入 design-template.md 重量档 | 维持现状 |
|---|---|---|---|---|
| 成本 | 模板一次撰写 ~130 行 + 规范两处增补 | 5.1 增补 ~4 行 | design-template 增 ~110 行 | 零 |
| 风险 | 单一样本外推(零默认值使错成本 = 章节删节) | 规则有、结构无,下游仍从空白摸索 | 两生命周期混排(流水产物 vs 活文档),实例化语义破坏 | 摸索成本逐项目重付 |
| 迁移代价 | 零(纯新增) | 零 | design-template 实例化者须辨别并删除整块骨架 | 零 |
| 可逆性 | 高(revert 单 commit) | 高 | 高(但存量实例已扩散,回撤脏) | — |

**方案 B 未入选**:R2 的模板复制原则是本体系文档生产的一致性基座,五类流水产物全有模板;设计系统是唯一被点名却无模板的类型,规则面补齐而结构面留白,下游首版仍得不到台账、裁决、版本纪律这些事故驱动机制——恰是本提案最有价值的部分。

**方案 C 未入选**:design-template 是流水产物模板(与 spec 同号、定稿先于 spec Active),设计系统是活文档(每项目一份、无状态机);两者生命周期与读者不同,合并使实例化者每次都面对「删与不删半份文档」的裁决。且 design-template 现 82 行,并入后近 200 行,轻量定位破坏。

**维持现状未入选**:5.1 留口即「待真实使用后增补」,前提已兑现;继续留白的成本不是零而是「每个自绘项目重付下游实践的三版摸索」。且本提案已把维持现状形态内置为降级路径(见影响与风险「退出条件」),采纳本提案不关闭回到现状的通道。

## 影响与风险

- **verify-docs 零影响**:新模板 `-template.md` 后缀落入既有豁免面(检查 2 / 8 / 11 对象排除、检查 5 目录级白名单);RFC 本体入 meta/ 后由检查 9 / 12 治理面覆盖,同 commit 登记注册表即合规。
- **单一样本外推风险(暴露度分层)**:骨架约六至七成为设计系统领域通行概念(token 三列表、语义一致、a11y 基线、版本纪律、4px 基网),样本暴露度低——2026-09-23 对 Material 3 / Carbon / Ant Design / Polaris / Primer / shadcn/ui 六系统官方文档结构会话内对表实证:第 1-8 节在有规范面的五家均有对偶,shadcn/ui 无规范面恰证适用判据「组件库项目默认不建」;三至四成机制(待回填台账、冲突裁决表、页面类型表形式化、索引化瘦身纪律)为样本特有,是真实暴露面——对表确认第 9 节治理面业界无对偶,属本模板差异化价值,亦无外部校验,失效信号机制为其唯一保护。「零默认值」防线只覆盖内容层错误(错成本 = 删节),不覆盖指导语层与形状层:指导语已去处方化(维度 / 立场标「自定」并给示例,不处方具体哲学);形状层靠裁剪走查(实例化第一步,结果记 v0.1 变更记录)把「删节」从许可变步骤与痕迹——裁剪记录同时是样本积累期的遥测面(哪些节被高频删除、哪些项目被迫模板外自造,即未来硬化或降级的直接依据)。

- **退出条件**:两份实践形态显著分叉且实例化率低 → 撤回模板,structure.md 5.1 回退纯生命周期规则(方案 B 由落选备选转为内置降级路径,本提案不关闭回到现状的通道)。

- **模板行数与自查线**:当前落地文本 187 行 / 14 章节,均摊 ~13 行每章节,与 design-template.md(~10 行每章节)同量级;自查线定为 **200 行**,超线的评审问题是「是否把内容写进了指导语」而非删节。150 行原线系按 AGENTS.md「每会话必读」的上下文经济类推,不适用于实例化时一次性加载的表单模板。指导语显式声明章节裁剪自由,实例化负担与项目规模成比例。
- **学习成本**:下游 AI 会话新增一个「自建设计系统时的必读模板」,但仅在设计/立项涉视觉场景按需加载,不进 AGENTS 路由表,日常会话零增量。

## 迁移与回滚计划

非破坏性变更(纯新增文件 + 两处规范文本增补),不适用分步迁移。已初始化项目升级时随模板体系整体更新,无追溯义务。回滚 = revert 落地 commit(模板文件、structure.md 5.1 末条、design-template.md 一行、decisions.md 一行、README 版本条目一并还原),无数据迁移。

**验证口径**:① `node docs/verify-docs.mjs` 默认与 `--template` 双模式全绿;② 落地模板文件 ≤ 200 行;③ 模板零具体视觉值(grep 无 `#[0-9a-fA-F]{6}` 形态色值;指导语中的机制性描述如「4.5:1」「≤ 2 个」不算视觉值);④ structure.md 5.1 末条含 design-system-template.md 链接与 `design-system.md` 实例化口径,「待真实使用后按需增补」字样移除;⑤ design-template.md「设计基准」行含实例化指引;⑥ AGENTS.md、verify-docs.mjs、manifest.txt 零改动(git diff 确认);⑦ 模板全文与 1.1 节落地文本逐字一致;⑧ 模板头部含裁剪走查步骤与 v0.1 裁剪记录要求;⑨ 指导语无处方性立场(grep 无「覆盖数据真实」「默认不用,列允许条件」类措辞残留,「自定」形态存在于维度与立场两处);⑩ 模板含「资产清单」节与同 slug 子目录口径,字段表「配套规范页」行含「免构建」,适用判据含「SHOULD 考虑精简版」与信号清单。
